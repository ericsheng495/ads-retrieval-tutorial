Its cited architectures address feature interactions and multi-task learning. Its last two references concern marketplace experiment design.

Understand calibration before the auction

Suppose one candidate has estimated per-impression conversion probability 0.02 and toy value 3; another has 0.01 and toy value 5. Expected toy values are 0.06 and 0.05. Doubling one group's probability estimates can change a decision even when its within-group ordering remains unchanged. This invented calculation explains why score scale can matter; it is not an auction specification.

For a practical check, bucket predictions and compare average probability with observed frequency using mature labels. Slice by meaningful populations and exposure definitions. A good overall number can hide a broken minority slice.

Understand selection and delayed feedback

Sketch a dataset with request ID, candidate IDs, displayed ID, prediction-time features, click time, and conversion time. Only displayed candidates can create display outcomes. A nonwinner's missing click is not an observed rejection. An immature conversion window should not silently become a settled negative.

These are two different issues: the earlier policy selected what was observed; delayed feedback determines when an observed outcome is complete. Sampling correction inside a retrieval loss does not resolve both problems.

Trace the model lifecycle

For your project, use the sequence: define labels and splits → build feature inputs → train → validate prediction and serving cost → register a checkpoint and its dependencies → stage a compatible serving deployment → experiment → monitor → update or roll back. This is a suggested learning workflow.

Write down what should happen if a genre feature is missing for 90% of new items, an index uses an old model, or conversion labels stop arriving. The correct response may require halting an update or using a fallback rather than increasing model complexity. Define the alarm and rollback evidence before simulating the fault.
