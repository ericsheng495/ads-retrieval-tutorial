Learning from negatives

Concept

Training examples give positive user/item pairs. To make their scores meaningful, compare them with candidate alternatives. In-batch sampling uses the other items already in a batch, avoiding a fresh full-catalog score matrix at each step. These alternatives are unobserved items, not proven dislikes.

Softmax turns a row of logits into probabilities over its sampled candidates. With one positive, negative log probability rewards a large positive score relative to the rest. This is a sampled contrastive objective, not the exact full-catalog loss.

What training changes

Initially the embedding coordinates are arbitrary. A loss supplies a numerical learning signal, and an optimizer adjusts the parameters to reduce it. A batch is a group of examples processed together; an epoch is a pass through training examples. These are training units, not serving stages.

If you only reward increasing positive scores, the model can raise many scores without useful separation. Comparing positives against alternatives asks it to learn a relative ordering. Three user/item pairs can generate a 3×3 score matrix: each user scores all three batch items, not just its paired item.

A candidate distribution is not a click probability

Softmax exponentiates scores and divides by their sum, so values sum to one over the supplied candidates. Add candidates and those probabilities can change. They are not automatically probabilities that the user clicks each item when shown. The ranking primer uses a different label and sigmoid model.

The positive usually begins on the matrix diagonal. Duplicate item columns and other known positives explain why “every off-diagonal entry is negative” can be wrong. The optimizer can learn contradictions if the supervision ignores that.

Worked example

Let one user's scores be [2, 1], with the first item positive. Its probability is exp(2)/(exp(2)+exp(1)) ≈ 0.731, and its loss is -log(0.731) ≈ 0.313. Divide scores by temperature 0.5: logits become [4, 2], positive probability becomes about 0.881, and loss about 0.127. A smaller temperature sharpens the distribution, but confidently wrong scores can produce larger losses and gradients.

Now let both columns represent the same positive item. Penalizing the second column as a negative contradicts the label. Our positive mask includes both:

loss(row) = logsumexp(all candidate logits)
            - logsumexp(positive candidate logits)

If all columns are positive, both terms match and loss is zero. Known training positives for the same user also enter the numerator. Held-out labels never do.

Application to this project

Popular movies appear repeatedly in batches, and users can have multiple observed positives. The mask avoids obvious contradictions, but cannot identify every movie a user would enjoy. Candidate sampling also favors popular items; lesson 5 explores it.

Implement it

  1. Calculate the two numeric losses above by hand and with tensors.
  2. Create a [B, B] matrix from the encoders and divide by temperature.
  3. Construct an item-equality positive mask; OR it with known training-positive membership.
  4. Use logsumexp for numerical stability; mask nonpositive numerator columns with negative infinity.
  5. Average row losses, call backward(), and inspect finite gradients.
  6. Run the duplicate-positive test, then compare against in_batch_loss in model.py.

Read Yi and Yang after implementing the basic loss; their correction mechanisms depend on the actual sampler and should not be pasted blindly onto this variant.
