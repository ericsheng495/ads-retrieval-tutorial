The ads serving layer

Concept

A high score does not imply an item can be served. Eligibility can depend on targeting, budgets, policy, inventory, or geography. Cold start asks what to do without interaction history. Freshness asks how quickly a changed catalog or model becomes available to retrieval.

These concerns interact: new items need representations, eligibility can change faster than vectors, and a new model defines a different embedding space.

Relevance, permission, and availability differ

An attractive ad can be unavailable because its campaign has no budget. It can fail targeting or policy checks regardless of model score. A prohibited candidate should not fill an empty slot just because few alternatives remain.

Separate content freshness, catalog freshness, eligibility freshness, and model freshness. A changed creative can require new vectors; a changed budget may only require metadata updates. A changed encoder may require a compatible new index rather than appending vectors to an old coordinate system.

Likewise, distinguish a completely new user from a sparse known user, and a new item from an unpopular trained item. A fallback is a defined alternative policy, such as eligible popularity, whose behavior you can test. It should not be an accidental zero-vector output.

Worked example

An ANN query returns items [A,B,C,D]; only C and D are eligible, but K=3. Filtering that result leaves two items. Overfetching six candidates might find a third; prefiltering searches only eligible candidates but may require index partitions, filter-aware search, or more expensive work.

Suppose a held-out positive is ineligible. Counting its absence as a model miss confuses relevance with feasibility. Report both the proportion of targets that are eligible and recall among eligible targets, along with empty-result rates.

Now imagine item vectors were encoded with model v1 while queries use v2. Vector dimensions can match even when their coordinates no longer mean the same thing. A shape check cannot detect this; compatible model/export metadata is required.

Application to this project

Use genre categories and deterministic mock budgets as an eligibility exercise. These are simulations, not real ads constraints. Hold out complete items to test content-only cold start, rather than claiming a rare training item is unseen. For new users, explicitly serve a popularity/content fallback.

Implement it

  1. Define an eligibility function with query-time attributes and test edge cases.
  2. Compare exact eligible search with ANN+filter+overfetch; measure eligible recall and latency.
  3. Train a content encoder, hold out item IDs, and score their content without an ID lookup.
  4. Insert a newly encoded item into an index and measure time-to-retrievable.
  5. Persist model hash, preprocessing version, ID mapping, and build time with the index.
  6. Reject mismatched query/index versions; separately test insertions, deletions, and budget updates.
  7. Simulate exploration slots and quantify candidate displacement.

Read DropoutNet and Facebook EBR. The existing export checker in ann.py guards paired artifacts; a persisted serving index and these ads behaviors remain your implementation exercises. Exploration's online benefit needs a real experiment.

Self-check

  • Which changes require recomputing vectors, and which can be eligibility metadata updates?
  • Why can simply appending an item fail after changing the embedding model?
  • What should happen when fewer than K eligible items exist?
