2. Explain the math with a three-example batch

For user vectors U and item vectors V, both [B, d], scores are S = U @ V.T / temperature, shape [B, B]. A row is one retrieval query.

  • [ ] Draw the 3×3 matrix and identify positive columns.
  • [ ] Explain why unobserved items may be false negatives.
  • [ ] Use item IDs [7, 7, 9]; show why diagonal-only cross entropy is wrong here.
  • [ ] Explain the reference loss: logsumexp(all) - logsumexp(positives) per row.
  • [ ] Show how known training positives enter the mask; explain why validation/test labels cannot.
  • [ ] Explain that normalized dot product is cosine; normalization removes norm information.
  • [ ] Explain how temperature scales logits and gradients; it does not change exact serving order for fixed vectors.

Normalization is a modeling choice, not a universal retrieval requirement. Without it, maximum inner product search can use vector norms as a signal. Our sampled contrastive objective approximates a retrieval learning task; it is not exact full-catalog softmax, nor a reproduction of DSSM or YouTube.

3. Rebuild the pieces yourself

git switch -c learn/v0

Create scratch/ and implement in this order, using the reference only to check:

  1. Load positive rows, deduplicate user/item pairs, remap IDs, split each user by timestamp.
  2. Hand-compute top-2 and Recall@2 on four items. Then implement full-catalog evaluation.
  3. Create an embedding and projection for each tower; check output shapes and norms.
  4. Implement the multi-positive loss using logsumexp. Backpropagate one batch.
  5. Shuffle training pairs, optimize with Adam, evaluate validation, save the best checkpoint.

Do not delete the reference to get started. Compare outputs on the same tiny fixture, then run your implementation on the fixed MovieLens split.
