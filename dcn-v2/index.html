DCN V2: a more expressive cross transformation

Concept

Review the original DCN layer: it scales all original coordinates by one projected scalar. DCN V2 enriches the cross transformation:

x_next = x0 ⊙ (W * x_current + b) + x_current

W is a learned matrix, * inside parentheses is matrix multiplication, and ⊙ is coordinate-wise multiplication. Each original coordinate now combines with a separately learned projection. Low-rank and mixture variants balance expressiveness with cost; stacked and parallel compositions combine cross and deep components differently. Wang et al., WWW 2021; preprint 2020.

Architecture

Its expert mixtures are an architecture mechanism for efficient crosses; do not equate them with MMoE's separate task gates merely because both use mixtures.

Worked example

Let x0=x_current=[1,2], b=[0,0], and W=[[1,0],[0,2]]. Then:

W*x_current = [1,4]
x0 ⊙ [1,4] = [1,8]
x_next = [1,8] + [1,2] = [2,10]

The second coordinate has its own scale rather than sharing one scalar with the first. For d=100, a dense d×d matrix has 10,000 entries. Factoring it into two rank-10 matrices uses 2,000 entries, before biases/gates. Lower rank saves parameters but restricts the transformation.

Implementation exercise

Implement a full-matrix cross layer and verify the toy arithmetic. For row-major batches, PyTorch's linear layer convention handles x @ W.T; be consistent with the column-vector equation above. Add a low-rank projection through a smaller intermediate dimension and compare shapes, cost, and validation behavior.

Keep preprocessing, label definition, optimizer budget, and serving measurement fixed when comparing DCN, DCN V2, and an MLP. A different gate count or embedding width also changes the experiment. Report the chosen variant, not just “DCN V2.”

Check your understanding

What restriction does the matrix relax? What expressiveness is lost with a low rank factorization? Which cost matters when this layer runs for every candidate?
