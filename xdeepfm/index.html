xDeepFM: explicit vector-wise interactions

Concept

DeepFM's explicit FM term is pairwise. xDeepFM adds a compressed interaction network (CIN) to build explicit higher-order interactions. It combines a linear branch, CIN, and a deep branch.

CIN forms coordinate-wise products between previous-layer feature vectors and original input feature vectors, then learns combinations across their feature map pairs. Sum pooling produces a representation for the prediction head. This preserves a particular vector-wise interaction structure, complementing the implicit patterns learned by the deep branch. Lian et al., KDD 2018.

Architecture

For previous map i and original field j, construct the vector H_previous[i,:] * X0[j,:]. A learned weight for a new map mixes these pair-product vectors; it is shared across the embedding-coordinate axis.

Worked example

Take two original toy fields [1,2] and [3,4]. Their coordinate-wise product is [3,8], while their dot product is the scalar 11. Keeping [3,8] allows a later layer to multiply with another field before pooling. That distinction is the reason “CIN is just an FM dot product repeated” misses important structure.

For a one-map toy CIN with only this pair's weight set to 1, the map output is [3,8], and sum pooling gives 11. Adding another layer can create higher-order products while still using original field vectors.

Implementation exercise

Use an input tensor [batch, fields, embedding_dim]. Build a one-layer CIN with explicit loops on two fields so every product is inspectable. Then vectorize pair creation and learned mixing; confirm the same toy output. Add pooling and combine with linear and MLP logits.

Compare FM-only explicit interactions against CIN at controlled capacity and training cost. Intermediate pair tensors can be large: count feature maps and embedding dimensions before expanding them. You are testing a mechanism, not reproducing the paper's benchmark by matching one forward pass.

Check your understanding

Where do interaction orders increase? What information is lost if you reduce every pair to a scalar before creating the next CIN layer?
