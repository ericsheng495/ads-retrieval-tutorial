Evaluation contract

Current protocol

MovieLens-100k ratings ≥4 count as positive feedback. Lower ratings are unused, not explicit negatives. Keep the earliest positive per user/item, discard users with fewer than three distinct positives, sort by timestamp then item ID, and hold out the last two positives per user for validation/test. IDs are remapped over the retained catalog, so items with no training positives can exist.

Validation filters that user's training positives. Test filters training and validation positives. The model is not retrained on validation. For every query, the held-out target must remain eligible. The same movie may be in training for other users; that is expected collaborative learning, not pair leakage.

This protocol is chronological within each user only. Other users' training events can occur after a user's evaluation time. It therefore does not establish global temporal safety. Phase 2 requires a global cutoff experiment, train-only feature statistics, a catalog available at query time, and explicit cold-user/item policies before making a deployment-like claim. Even the catalog definition is an assumption here; validation/test metadata informs the remapped vocabulary.

Metrics

With one target per user, Recall@K equals HitRate@K: mean(target is present among the first K eligible predictions). It is not precision, CTR, or a calibrated conversion probability. Scores are computed against the full retained catalog, not sampled distractors. Ties break by catalog ID. Excluded slots are padded with -1 if necessary.

The exact expected random recall is mean(min(K / eligible_catalog_size_for_user, 1)). K / n_items only applies to an unfiltered catalog with K ≤ n_items. Popularity counts come from training only. Its test and validation metrics use the same exclusions as the learned model. Test scores from repeated runs can influence human choices; do not call the resulting model selection unbiased.

Training assumptions

In-batch candidates follow the training interaction distribution, not a uniform catalog distribution. Other examples are unobserved candidates, potentially false negatives. Duplicate item columns and known training positives contribute to positive probability mass in the reference loss. This does not remove all false negatives or correct exposure bias. The dense positive mask is practical only for this small dataset; use sparse or indexed membership at scale.

logQ correction concerns the candidate sampling mechanism; it does not solve impression/auction selection bias. Derive Q for the actual batch/mixed sampler, including duplicates and expected counts, before applying a correction. Do not subtract training popularity from inference scores by habit. See Yi and Yang.

Required Phase 2 report

  • [ ] Identical splits, candidates, exclusions, and K across random/popularity/MF/two-tower.
  • [ ] A plain dot-product MF baseline trained with a documented loss; the reference's linear towers are already closely related to MF.
  • [ ] Head/tail groups defined with training counts; report group sizes and cold items.
  • [ ] Light/heavy groups defined with training user counts, not future activity.
  • [ ] Per-user timestamp audit plus the separate global cutoff evaluation.
  • [ ] Several seeds and uncertainty estimates for claims beyond the smoke test.

ANN neighbor overlap and held-out-target Recall@K are distinct: the former asks whether an index approximates exact vector search; the latter asks whether the model retrieves a relevant target. An ANN benchmark over all user embeddings is not a future-query production latency measurement.

These evaluation risks connect to Schnabel et al. (2016).
