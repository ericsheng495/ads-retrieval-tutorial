DeepFM: pairwise interactions plus a deep branch

Concept

A factorization machine (FM) models pairwise feature interactions through dot products of learned feature vectors. Rather than fitting an independent coefficient for every possible pair, it shares parameters through those vectors.

DeepFM combines a linear/FM component with a deep component and shares their input embeddings. The FM branch models low-order interactions explicitly; the deep branch learns more complex nonlinear patterns. It avoids requiring a separate hand-engineered cross-feature input for the wide component. Guo et al., 2017.

Architecture

For scalar encoded features xi, the pair term is sum over i<j of dot(vi,vj)*xi*xj. “Feature vector” here means an embedding for a feature value; the interaction is not restricted to one user vector and one whole-item vector as in the retrieval reference.

Worked example

Three active toy features have vectors v1=[1,0], v2=[0.5,1], and v3=[0,1], with all xi=1. Their pair contributions are 0.5, 0, and 1, so the total is 1.5. Linear terms and a deep contribution would also enter the final logit before its sigmoid.

You can compute the same pair sum efficiently using:

0.5 * sum_coordinates((sum_i vi*xi)^2 - sum_i (vi*xi)^2)

For these vectors the coordinate totals are [1.5,2]; squared totals sum to 6.25, individual squared values sum to 3.25, and half their difference is 1.5. This avoids an explicit loop over every feature pair.

Implementation exercise

Implement both the loop and efficient formula and compare outputs and gradients on a tiny batch. Build a flattened-embedding MLP branch using the same embedding parameters, then combine branch logits. Ablate FM-only and deep-only.

Keep fields distinct and handle numeric scaling and unknown categories explicitly. Measure data sparsity and validation behavior. Better parameter sharing is useful only if the shared patterns fit your data; it is not a universal performance guarantee.
